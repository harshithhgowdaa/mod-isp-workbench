# Hackathon readiness audit

**Audit date:** 2026-11-08
**Sources reviewed:** MOD-ISP Stage 5 blueprint, Computer Vision Hackathon 2026 problem statement and the supplied rubric screenshot, current repository and run artifacts.

## Verdict

This is a working research prototype with useful measured results. It is **not 100/100 ready**, and the available evidence cannot predict a contest score. The two supplied screenshots now show five criteria whose row maxima total 100 (Evaluation 25, Implementation 20, UI/UX and deployment 15, Project documentation 15, Demo/Viva 25). The rubric text still says Demo/Viva plus five other criteria, although only four other rows are visible; several displayed top-band ranges also stop at 15 despite row maxima of 20 or 25. The missing sixth row and score-band mapping are ambiguous, so do not infer a precise score from this copy.

The strongest defensible result is the separate SIDD-CC sRGB denoising benchmark. The strongest current Bayer result is much smaller and does not demonstrate efficient gating. The blueprint's proposed device, quality, parameter, and speed numbers are targets, not measurements from this implementation.

Therefore, **all 230 SIDD-CC pairs are accounted for in both modalities, but not all are gradient-training examples**: validation and calibration pairs are correctly kept out of optimizer updates. The larger datasets named or implied by the supplied links have not all been used. Full SIDD / S24 training cannot be completed in the current environment: neither an external drive nor a cloud training workspace is available, and local free space is about 7.3 GiB.

“All pairs accounted for” does not mean every pixel was used for optimization. The latest Bayer run used three distinct random 128×128 crops per training capture per epoch (166 captures × 3 × 5 epochs = 2,490 optimizer steps). It selected the best epoch using five deterministic center/corner 128×128 validation crops per pair. The sRGB run made one random 256×256 crop per training pair per epoch in batches (194 pairs × 10 epochs); flips and transposes were applied. Each training pair was visited, but most image pixels were never sampled.

### What “all training data” means here

The supplied SIDD page describes multiple distinct releases. This project did **not** train on the full SIDD-Full collection (~24,000 images), nor did it use the separate SIDD-Small or SIDD-Medium releases. It trained on the SIDD-CC paired training release only. Within SIDD-CC, all 230 train pairs per modality are assigned once to a training, validation, or calibration split. The 28 RAW calibration pairs are reserved for gate and quantization calibration, not optimizer updates. This is the correct leakage-aware use of those pairs; putting validation/calibration pairs into training would invalidate the reported evaluations.

The user-supplied Samsung repository is source code plus pretrained weights and dataset preparation instructions, not a training corpus. This project used its generic-lite NAFNet definition/checkpoint to initialize the **separate rendered-sRGB denoiser**. It did not train on Samsung S24, Zurich RAW-to-sRGB, or MIT-Adobe5K. Those larger, more diverse datasets could improve coverage, but they require access, preprocessing, alignment, license review, and a new scene/camera-disjoint protocol. The existing SIDD-CC checkpoint metrics must not be represented as having used them.

**Acquisition recheck (2026-11-08):** the official SIDD-Full link list points to Mirror 1 on `130.63.97.225` and Mirror 2 on CodaLab. A one-byte HTTP range probe to each mirror timed out from this machine; no SIDD-Full files were downloaded. The S24 dataset README describes 3,224 RAW/sRGB captures and links its training archive through Sync.com, but the current local filesystem has only 7.8 GB free and the landing response did not expose an archive size. These are access/storage blockers, not a claim that the data is unavailable to other users or environments. SIDD-Full is also not a substitute for the paper's ZRR/MAI21 training sets.

## Current measured evidence

### Bayer RAW-to-sRGB

The current production checkpoint is the multi-crop candidate in `models/mod_isp.pt` (29,980 parameters, 2,490 optimizer updates, five epochs, seed 2027). It fine-tunes the prior 2023-MetaISP-distilled student on all 166 training pairs using three distinct random 128×128 crops per pair per epoch. The best checkpoint was selected on five fixed center/corner crops from each of the 36 scene-disjoint validation pairs (validation L1 0.03857). We then compared the previous checkpoint and this candidate on the same 36 validation captures using identical 256×256 center crops:

| Path/checkpoint | PSNR ↑ dB | SSIM ↑ | Delta E 2000 ↓ | Tiled LPIPS ↓ |
|---|---:|---:|---:|---:|
| Classical baseline | 15.693 | 0.6037 | 14.843 | 0.2478 |
| Previous Learned checkpoint | 20.479 | 0.7577 | 12.143 | 0.3377 |
| Current multi-crop Learned | 23.813 | 0.8393 | 9.663 | 0.2584 |

Against the previous Learned checkpoint, the new candidate wins 34/36 PSNR, 36/36 SSIM, 34/36 Delta E, and 36/36 LPIPS comparisons. Mean changes are +3.334 dB PSNR, +0.0817 SSIM, −2.480 Delta E, and −0.0793 LPIPS. This is a paired comparison on the validation scene, which was used for checkpoint selection; it is **not** an untouched test or a contest leaderboard score. It is materially stronger evidence than the earlier one-crop run, but broad camera generalization still needs a separate test set. The report is `evaluation_siddcc_bayer_multicrop_256.json`; training details are in `models/mod_isp.json`.

The INT8 LiteRT export was regenerated from this checkpoint with 256 representative tiles spanning all 28 calibration captures. On 72 held-out validation tiles, mean/median/p95 output MAE was 0.00625/0.00302/0.01211; maximum tile MAE was 0.05284 and mean input clipping was 0.00044%. CPU tile latency median/p95 was 0.315/0.345 ms under TensorFlow Lite XNNPACK on this Mac. This is CPU evidence only; no phone or NPU delegate was available. Full report: `litert_verification_multicrop.json`.

The earlier relative-variance gate was recalibrated against the multi-crop checkpoint. Under a 0.5 dB calibration PSNR-loss budget, it selected a 100% neural route: calibration PSNR fell by 2.703 dB at a 95% route. On the 36-pair validation set, that earlier gate equaled all-neural output and routed 100%; mean warm latency was 50.45 ms for all-neural and 48.54 ms for the gate, a difference too small and noisy to claim computation savings. The app now uses the separate RAW-statistics gate documented below. See `models/gate.json` and `gate_validation_multicrop.json`.

Stratifying those same captures by SIDD camera family exposes a camera-dependent quality gap: on the two N6 crops, Learned averages 17.07 dB PSNR / 0.6220 SSIM / 14.45 Delta E / 0.4401 LPIPS, versus Classical at 16.74 / 0.8591 / 10.70 / 0.1778. Evaluation of the separate 28-capture calibration scene shows substantial scene-by-camera interaction: N6 favors Learned by 11.81 dB there but by only 0.34 dB on validation; G4 and GP favor Classical on calibration, but Learned on validation. A simple camera-family gate would therefore overfit these two scene samples. The later training-fitted tile gate experiment below reduces inference calls but does not meet the quality budget.

A second experiment fitted a ridge predictor from RAW intensity, high-pass, and local-variation statistics on 256-pixel center crops from the calibration scene, then chose its threshold to preserve mean calibration PSNR within 0.5 dB. It met that budget while routing 39.3% of calibration crops to Learned. On the untouched validation scene it routed 22.2% to Learned, but mean PSNR was 18.444 dB versus 20.479 dB for all-Learned (−2.035 dB); SSIM fell 0.0229, Delta E was nearly unchanged, and LPIPS improved 0.1180. Although predicted benefit correlated 0.904 with measured benefit, its 2.72 dB MAE and the validation quality regression make it unsuitable for deployment. The 77.8% figure is a theoretical reduction in image-level model invocations on these crops, not a full-resolution latency/MAC measurement. See `evaluate_image_gate.py` and `image_gate_evaluation.json`.

A tile-level experiment fit a ridge regressor on 12 RAW-only statistics and 700 tile labels from the calibration scene. It selected a 30.0% neural route within the 0.5 dB calibration budget (−0.481 dB). On 36 validation crops, the frozen policy routed 24.78%, but mean PSNR regressed by 4.442 dB (20.479→16.037); SSIM regressed 0.0736 and Delta E worsened by 1.686, while LPIPS improved 0.0977. The gate artifact is explicitly marked ineligible and is not connected to the app. The nominal 75.22% skipped-tile figure is not a measured latency or MAC reduction. See `calibrate_tile_quality_gate.py`, `tile_gate_evaluation.json`, and `models/gate_quality_tile.json`.

A further score-rank gate was calibrated by selecting the highest predicted-benefit tiles within each image, to remove the cross-capture score-offset problem. ### Rendered sRGB

The strict split trained 194 pairs for 10 epochs and selected epoch 10 on 36 scene-held-out pairs (mean PSNR 34.411→37.317 dB from the Samsung generic-lite initialization). On the untouched 928-block test benchmark, noisy input measured 26.119 dB PSNR / 0.4251 SSIM, the initialization 29.303 / 0.5738, and the new checkpoint 33.755 / 0.7757. These are means across benchmark blocks, not official leaderboard scores.

On the 928-block deterministic stress sweep, the active model recovered +7.299 dB with additional Gaussian σ=0.02, +5.683 dB at σ=0.05, and +0.398 dB at 0.5× exposure. JPEG quality 30 regressed by −0.528 dB PSNR, while SSIM improved slightly. A separate exposure/noise-augmented fine-tune improved the 0.5× exposure result by 0.380 dB, but lost 0.954 dB on the published noisy test blocks and regressed more under extra Gaussian noise. It was rejected and is not loaded by the application. These are synthetic sRGB-domain stresses, not Bayer RAW or real-camera low-light results; `docs/robustness-analysis.md` contains the protocol and full table. The published test blocks were used once to reject this candidate and must not be called untouched for future candidate selection.

## 2026-11-09 full SIDD-CC training addendum

After the initial audit, the complete locally available SIDD-CC RAW training split was staged without copying data and used for a separate 25-epoch, 1,010,433-parameter paper-informed 2024 MetaISP reproduction. A 29,980-parameter student was distilled for five epochs from its exported teacher. Both runs used all 230 paired SIDD-CC RAW training captures with one random 128×128 crop per pair per epoch; neither used a validation set or the official RAW test blocks for checkpoint selection. This updates the earlier statement that the local 2024 reproduction used only 166 training pairs. It does not mean the full SIDD collection, Samsung S24, Zurich, MAI21, or official MetaISP weights were available or used.

An independent official RAW test-block experiment split 14 scenes (448 blocks) for gate calibration and 15 disjoint scenes (480 blocks) for held-out validation. Because test-frame metadata are absent, camera-level median white-balance gains and CFA patterns inferred from training metadata were used as documented proxies. With a 0.5 dB PSNR-loss budget, the ExtraTrees gate selected 100% neural routing; on held-out blocks it reduced neural tile calls by 0% and measured 46.44 ms mean warm Hybrid latency versus 19.25 ms Learned. Therefore the new experiment does not achieve the gate's computation-reduction objective. Its proxy metadata, block crops, full metrics, commands, and artifacts are documented in [the full-train and gate report](siddcc-fulltrain-gate-evaluation.md). This result does not alter the production checkpoint or gate.
